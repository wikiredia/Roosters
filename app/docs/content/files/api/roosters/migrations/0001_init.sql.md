The **first schema** of Roosters+ v2: every table, with comments. Conventions:

- `DATETIME` columns are **UTC**; times of day are **minutes since midnight in the school's timezone**
  (`start_min`, `end_min`, `since_min`).
- Soft delete only where history matters (`sources.deleted_at`); accounts are deleted for real
  (`accounts.delete_user`).
- **Data minimisation:** no teachers, no free text from Untis, no event descriptions from calendars.

Later changes: `0002_guests_admin.sql` (guests, turned-off accounts, the admin log).

## `auth_identities`

How someone signs in: Apple, Google or a code by e-mail (`subject` = the Apple/Google user id, or the address). One user can have several; a verified e-mail links them (`r_auth._sign_in`).

## `blocks`

Who blocked whom; a block ends the friendship and hides you from each other.

## `campuses`

Campuses of a school. Same campus matters for breaks (`logic.min_break`).

## `checkins`

Today's status: chilling (still around after class), want_chill, home (going home early), absent. Changes the break logic (`logic.day_info`).

## `class_lessons`

The lessons of a class: day, minutes, course, room, `state` (normal, cancelled, changed, extra, exam, removed), a `fingerprint` for change detection, and `changed_at` (shown as 'new' in the app for 48 hours).

## `friend_requests`

Requests within a school (pending, accepted, declined, cancelled).

## `friendships`

Two rows per friendship (A→B and B→A). `visibility` = what `user_id` shows `friend_id`: the full timetable or only free/busy.

## `hidden_courses`

Courses a user switched off ('I don't take this one'), for all their sources.

## `idempotency_keys`

Answers to writes with an `Idempotency-Key`, so a retry after a lost answer gets the same answer instead of running twice (`idempotency.py`).

## `invites`

Invite links (`<PUBLIC_URL>/i/<code>`): 8 characters, 30 days, up to 50 uses.

## `jobs`

The job queue (`jobs.py`).

## `login_codes`

6-digit codes, only as keyed hashes (`crypto.keyed_hash`), with expiry and an attempt counter.

## `notifications`

In-app notifications (and later push), stored as kind + payload; the app writes the text in the user's language. `dedupe` stops the same change from being reported twice.

## `school_classes`

One row per class in Untis. Its timetable is fetched **once per class** and shared by everyone who follows it (`sync.sync_class`); `last_sync`/`last_ok`/`last_error` drive the app's 'fetching…' state and the console's sync errors.

## `schools`

A school: slug, names, country, timezone, Untis server and login name, `active` (shown in onboarding), when its class list was last fetched.

## `sessions`

One per signed-in device: the refresh-token hash (rotated on every refresh), the previous hash (to recognise a retry after a lost answer), device name, platform and expiry. Revoking a session signs the device out at once (`deps.auth`).

## `settings`

Key/value store for runtime settings (unused for now; kept for feature flags).

## `source_lessons`

Lessons from personal calendar links, per source and user; same columns and change detection as `class_lessons`.

## `sources`

A timetable source of a user: `untis` follows a school class (with include/exclude course filters in `config`), `ics` is a personal calendar link (encrypted in `secret_enc`).

## `users`

An account: display name, e-mail (NULL for guests and Apple 'hide my e-mail' without a verified address), locale, school and campus, avatar colour, ghost mode until, when onboarding was finished. Later: `is_guest`, `disabled_at`.
